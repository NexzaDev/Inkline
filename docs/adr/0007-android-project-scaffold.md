# 0007 Android project scaffold

- Status: accepted
- Date: 2026-11-12
- Deciders: Inkline maintainers
- Related: `docs/CI.md`, `docs/ARCHITECTURE.md`

## Context

Tauri 2 generates the Android Gradle project with `tauri android init`. The
generated tree is normally committed, because it is the project: the manifest,
the launcher icons, the Gradle wiring and the Kotlin entry activity all live
there.

Two of the generated defaults conflict with this project:

1. The template manifest declares `android.permission.INTERNET`. The release
   build must not declare it. Removing it unconditionally would break
   `tauri android dev`, which needs cleartext HTTP to the Vite dev server.
2. The template ships explanatory comments in the manifest, the theme files, the
   Gradle properties, the ProGuard file and one Kotlin task. The project forbids
   comments in code and configuration files.

The generated tree also changes underneath a committed project: running
`tauri android init` again re-creates files that were deleted and rewrites
`buildSrc/.../BuildTask.kt`.

## Decision

Commit `src-tauri/gen/android`, generated with `@tauri-apps/cli` `2.12.4`, and
keep these files verbatim as generated: `gradlew`, `gradlew.bat`,
`gradle/wrapper/gradle-wrapper.jar`, `.gitignore`, `app/.gitignore`. They are
third-party bootstrap files, not project code, and editing them would break the
checksum expectations of the wrapper.

Everything else is normalised once and reviewed:

- `app/src/main/AndroidManifest.xml` declares no permissions, disables backups,
  enables RTL, sets `adjustResize` for the keyboard and keeps Tauri's
  `FileProvider`.
- `app/src/debug/AndroidManifest.xml` adds `INTERNET` for debug builds only, so
  the release APK cannot reach the network even by accident.
- Comments are removed from the manifest, the themes, `gradle.properties`,
  `buildSrc/.../BuildTask.kt` and `.editorconfig`. `app/proguard-rules.pro` is
  kept, empty, because the release build globs it.
- Template leftovers that nothing references are deleted: `colors.xml` with the
  Material palette, `layout/activity_main.xml`, `drawable/ic_launcher_background.xml`,
  `drawable-v24/ic_launcher_foreground.xml`.

Versions are pinned by the generator and by this record: Gradle 9.6.1, Android
Gradle Plugin 9.3.1, Kotlin 2.2.10, `compileSdk` and `targetSdk` 37,
`minSdk` 26, `applicationId` `dev.nexza.inkline`, NDK r29 in CI.

## Consequences

- `tauri android init` is not run again on a clean tree without re-applying the
  normalisation. Phase 3 adds `scripts/android-manifest.sh`, which owns the
  manifest content (intent filters included) and rewrites it from the
  configuration, so regenerating the project cannot silently lose the filters or
  reintroduce `INTERNET`.
- The Gradle build calls back into the Tauri CLI through
  `npm run -- tauri android android-studio-script`, so the repository root needs
  `node_modules` installed before Gradle runs. CI does that explicitly; a stale
  root `package-lock.json` therefore breaks the Android build, not just the JS
  tooling.
- The launcher icon is temporary. `design/icon/` holds a placeholder mark that
  Phase 5 replaces; the mipmaps in the generated project are regenerated by
  `npx tauri icon design/icon/icon-manifest.json` from those sources.
